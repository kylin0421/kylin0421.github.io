# 本地博客编辑器

双击仓库根目录的 `start-editor.bat`（或在 PowerShell 中运行 `./start-editor.ps1`）即可启动。它会自动打开浏览器中的编辑界面。

默认使用 4310 端口；如果被其他程序占用，会尝试后续端口，并在服务就绪后打开实际地址。浏览器草稿按地址隔离，端口改变后，原地址的未发布草稿不会自动出现在新地址。

每次点击“保存并发布”或按 `Ctrl/⌘ + S` 都会：保存当前文章、自动更新内部的最后修改时间、只暂存这篇文章及正文引用的上传媒体、创建 Git 提交并推送到 `origin`。左侧列表按日记日期（文章文件名中的日期）排序；新文章可在发布前设置该日期。编辑中的未发布内容会自动保存为这台电脑浏览器中的草稿，切换日记或刷新页面后也可恢复；发布成功后草稿自动清除。GitHub Pages 随后会自行重新发布站点。

如果内容与已发布版本完全相同，编辑器会提示“无需提交或推送”，不会将 Git 的 `nothing to commit` 当成错误。

这个工具完全在本机运行，只监听 `127.0.0.1`，不需要安装任何 npm 包。首次使用前请确认本机 Node.js 与 Git 已经安装、Git 已配置身份，并且 GitHub 推送凭据可用。

## 插入图片和视频

打开任意文章或新建日记，在正文中放置光标，然后点击“插入图片”或“上传视频”。可多选，也可把文件拖进正文、直接粘贴截图。支持 JPG、PNG、GIF、WebP、MP4 和 WebM，每个文件最多 50 MB。MP4 推荐使用 H.264 编码；上传功能不负责转码。

上传过程中显示进度，完成后在光标位置插入图片 Markdown 或带播放控件的视频 HTML，下方“本文媒体预览”可查看图片、播放视频。可修改图片 Markdown 方括号中的文字作为替代文本。公开博客使用同一套响应式媒体样式。

上传只将文件保存到本机 `assets/media/`，不会立即提交或推送。点击“保存并发布”时，当前文章和它引用的上传文件一起提交。未引用的文件保留在本机，不会被其他文章的发布带上；删除正文中的引用不会自动删除文件，避免破坏其他文章的共享引用。上传文件使用唯一名称，重名不会覆盖。

文件随 Git 仓库发布，不使用第三方图床。大视频请先压缩；建议避免长期累积大量视频文件。

验证：运行 `node editor/test-media.js`，会在系统临时目录创建隔离仓库和本地 Git 远端，验证上传、格式检查、视频分段读取及文章和媒体一起发布，不触碰真实远端。

ENGINEERING NOTES · 20 OCTOBER 2026

A conversational guide,
with a face for each state.

This independent page adds spoken interaction to Linxiang Su’s existing GitHub Pages site. It uses a small browser orchestrator, streamed DeepSeek responses, browser speech services, and four generated portraits. The existing homepage, posts, and text-chat interface retain their original behavior.

What this is: a deployed, interruptible, turn-based voice interface. It is not a full-duplex speech-to-speech model. Hands-free interruption is experimental; microphone accuracy, acoustic echo rejection and perceived latency still require real-device testing.

3. Turn taking and interruption

Final recognition results settle for 650 ms before submission. Interim text receives a longer 1,500 ms pause allowance. These timers start when recognition results arrive, not at the exact last acoustic sample. Slow speech and mid-sentence pauses can therefore trigger a premature turn. Starting another turn cancels the previous one.

ModeBehavior
Speaker mode (default)Recognition pauses while the guide speaks to reduce self-transcription. Click Interrupt to stop playback immediately and resume listening. Recognition may continue during generation and gaps between phrases.
Headphone modeRecognition stays active during playback. Nontrivial partial transcripts trigger interruption, with simple echo and backchannel filters. This is a heuristic, not learned semantic turn detection.
Text modeTyping a new question cancels the previous answer. Read-aloud is optional; unsupported speech browsers retain full text interaction.

Cancellation increments a generation ID, aborts the fetch, cancels speech synthesis and empties the application’s phrase queue. Every stream update and utterance callback checks its generation ID. An old callback cannot restart playback, alter the new state or append words to the next turn. Canceling the browser response also cancels the Worker’s upstream reader; request abort is linked to the provider request. This is best-effort cancellation and does not guarantee that the provider stops billing instantly.

Conversation history tracks generated text separately from confirmed playback. Word-boundary events confirm only preceding characters; an utterance’s end confirms its remaining text. Interrupted voice turns send only that confirmed prefix to the next request. If a browser supplies no word boundaries, the unfinished utterance is conservatively omitted. Completed text-only replies use their displayed text. History is bounded to four prior exchanges.

4. Latency optimizations and measurements

  • Non-thinking generation, concise replies, streamed text, and phrase-level synthesis overlap generation with playback.
  • English/Chinese sentence boundaries, soft punctuation and a long-phrase limit release speakable chunks. Incomplete Markdown links are held until safe to clean.
  • The server prioritizes profile/CV and query-ranked documents, with at most five documents and 10,000 characters per document for voice. Knowledge is cached for 60 seconds.
  • One preloaded sheet makes all portrait states immediately available. Cancellation happens locally.

Observed production HTTP smoke checks, 20 October 2026: two requests returned first text/first body chunks in approximately 3.89 s and 1.56 s, with complete streams in 4.36 s and 1.91 s. The second followed an earlier request, but cache residency and routing were not controlled. These are two observations, not a benchmark or evidence of subsecond conversation.

The page reports first-text and speech-start timing from request submission. The synthesis start event is a playback proxy, not microphone-measured first audible sound; ASR endpoint delay is excluded. No acoustic P50/P95, false-interruption rate or real-microphone evaluation is claimed.

A useful evaluation should separately measure last spoken sample → submitted turn → first text → first audible response. Collect at least 30 turns per device/language/network condition, and report P50/P95, premature endpoints, echo-triggered interruptions, missed interruptions and transcript errors. Compare speaker mode with headphones rather than merging them into one average.

6. Privacy and operating limits

The API key lives in the existing service’s secret runtime configuration, never in the frontend, generated documentation or GitHub source. The browser sends transcripts to the service, which sends them to DeepSeek. Browser speech services may process input audio or synthesis remotely according to their own implementation and policies. This project does not record audio, persist conversation text or use localStorage for transcripts; provider/platform retention is not controlled by this application.

CORS restricts browser calls to the website and service origins. It is not authentication and does not prevent direct API clients from spoofing an Origin header. Shared durable limits allow 20 requests per IP-derived hourly bucket and 150 per day for the site, across both text and voice routes. Stored quota identifiers use a rotating salted hash rather than a raw address. These are request limits, not an exact currency spending cap; interrupted requests still consume quota. No dedicated per-session server concurrency lock or bot challenge has been added.

7. Verification and maintenance

Automated tests cover existing text-chat behavior and quotas; voice routing, streaming options, fragmented UTF-8 and SSE, malformed/truncated responses and upstream cancellation; phrase segmentation, incomplete links, basic echo/backchannel filtering, history bounds and exclusion of unheard words. The browser page is also inspected for rendering and text interaction. Real acoustic conversation requires a human microphone/headphone test; synthetic callbacks cannot establish voice quality.

Frontend files are under voice/ and assets/voice/. Server source is mirrored under chat-service/, excluded from Jekyll output, and deployed separately to the existing Sites project. GitHub Pages publishes the independent /voice/ page. Changing the browser bundle does not update the Worker; changing the Worker does not publish the static page.

For a more robust next version, replace browser ASR/TTS with authenticated, short-lived speech sessions and a dedicated streaming audio service. Add acoustic VAD, echo cancellation, provider word timestamps, bounded concurrency and measured endpoint detection. The current generation-ID and heard-history rules can remain. Speculative generation should wait until baseline latency and cancellation costs have been measured.
